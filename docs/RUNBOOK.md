# DWELL — запуск и инциденты

## Переменные окружения

| Переменная | Обязательна | Смысл |
|---|---|---|
| `RPC_URL` | да | узел Robinhood Chain |
| `REWARD_VAULT` | да | адрес развёрнутого `RewardVault` |
| `MIN_BALANCE` | да | порог участия, в целых токенах |
| `PROJECT_TOKEN` | да | адрес токена проекта: по нему считается вес. **Не** TSLA |
| `DATABASE_PATH` | да | файл SQLite |
| `KEEPER_PRIVATE_KEY` | да | горячий ключ кипера |
| `PORT` | нет | по умолчанию 8787 |
| `DRY_RUN` | нет | **по умолчанию включён**; снимается только точной строкой `false` |
| `CONVERSION_THRESHOLD_WEI` | нет | по умолчанию 1e15, около $2 |

`DRY_RUN` включён по умолчанию намеренно: забытая переменная обязана давать
безопасное состояние, а не публикацию реальных денег. Любое значение кроме
строки `false` — включая `true`, `0`, `no` и пустую строку — оставляет
защиту на месте.

Запуск:

```bash
node offchain/src/main.ts
```

Сборки нет: Node 24 исполняет TypeScript напрямую.

## Локальный просмотр

Посмотреть страницу без развёрнутого вольта, запущенного токена и ключа кипера:

```bash
cd offchain && npm run dev        # http://127.0.0.1:8787
```

Роутер, обработчики, хранилища и отдача статики здесь **производственные** —
подменён только читатель цепочки, плюс тикер, начисляющий присутствующим, чтобы
на странице было чему двигаться. Ни сети, ни ключа. Клейм не сработает: ему
нужен настоящий вольт.

| Переменная | Смысл |
|---|---|
| `DEV_BALANCE` | сколько токенов «видит» фейковая цепочка у любого адреса, по умолчанию 250000 |
| `MIN_BALANCE` | порог, по умолчанию 100000 — поставьте `DEV_BALANCE=1000`, чтобы увидеть состояние «баланса не хватает» |

Художка страницы генерируется, а не лежит файлами:

```bash
cd offchain && npm run art
```

## Последовательность запуска

**Заливка вольта — спусковой крючок, а не подготовка.** Раздача открывается
первой эпохой, в которой выплата действительно произошла, а пустой вольт
выплатить не может. Поэтому деньги в вольт кладутся последними, когда всё
остальное уже проверено на живых данных.

1. Развернуть `RewardVault`, **верифицировать исходник** на Blockscout
2. Выставить `maxAllocationIncreasePerRoot` под размер банка и форму раздачи
3. Запустить токен, **указать адрес кипера получателем creator fee**
4. Поднять процесс: настоящий `PROJECT_TOKEN`, **чистая база**,
   `DRY_RUN=false`, **вольт пуст**
5. Убедиться на живых данных, что хартбиты идут, эпохи закрываются, майнеры
   считаются, а релиз равен нулю
6. **Залить TSLA в вольт** — с этой минуты идёт раздача
7. Через 6 эпох выходит первый корень, ещё через `CLAIM_DELAY` он клеймится
8. Поднимать потолок по мере накопления доверия

Пункт 1 предшествует пункту 3 намеренно: контракт должен быть открыт для
проверки до того, как участники понесут деньги.

Пункт 4 с пустым вольтом безопасен полностью: релиз равен нулю, `allocate`
не кладёт ни одной доли, кумулятивы не сохраняются, `publishIfDue` выходит
на `nothing allocated yet` не отправив транзакции. Газ при этом не тратится
вообще.

### Чего делать нельзя

**Держать вольт заряженным при `DRY_RUN=true`.** В этом режиме начисления
копятся в журнале, но корни не публикуются. При переключении в боевой режим
накопленное поедет одним корнем и упрётся в потолок. Пустой вольт при
`DRY_RUN=true` безопасен, заряженный — нет.

**Запускать боевой процесс на базе, в которой уже есть посчитанные эпохи.**
Репетиция ведётся с отдельным `DATABASE_PATH`. Окно раздачи считается по
эпохам, в которых была выплата, поэтому чужая база означает окно,
израсходованное неизвестно на что.

### Конвертер тоже умеет заряжать вольт

`convertFeesIfDue` меняет ETH сверх `GAS_RESERVE_WEI` на TSLA и отправляет
результат **прямо в вольт**. Значит после запуска токена вольт может
зарядиться сам, как только на кипере накопится `GAS_RESERVE_WEI` плюс
`CONVERSION_THRESHOLD_WEI` — и раздача откроется без ручной заливки, на
случайную мелочь, потратив на неё слот окна.

Между пунктами 4 и 6 это управляется одним из двух способов: либо проверка
занимает минуты и заведомо укладывается до накопления порога, либо
`CONVERSION_THRESHOLD_WEI` на время проверки поднимается заведомо высоко и
опускается сразу после заливки.

## Что нужно сделать до запуска

- **Адрес токена проекта.** Задаётся переменной `PROJECT_TOKEN` и обязателен:
  без него процесс не поднимется. Заглушки больше нет — иначе вес считался бы
  по TSLA и майнили бы держатели Tesla, а не держатели токена проекта
- **Ставка creator fee** выбранного лаунчпада — выяснить фактическое
  значение и подставить в расчёт притока
- **Получатель creator fee — адрес кипера.** `convertFeesIfDue` читает
  баланс ETH того же кошелька, которым воркер подписывает; комиссии,
  пришедшие куда-то ещё, до вольта не доедут
- Четыре параметра: предзаряд вольта, `MIN_BALANCE`, эмиссия токена,
  стартовый `maxAllocationIncreasePerRoot`

## Инциденты

**Watchdog поставил паузу.** Опубликованный корень не следует из журнала. Не
снимать паузу до выяснения. Сверить таблицу `roots` с событиями
`RootPublished` в цепочке. Причин ровно три: ключом кипера воспользовался
кто-то другой, база разошлась с расчётом, воркер отправил не то, что
посчитал.

**Воркер отстал больше чем на 10 минут.** Состояние на узле живёт 6000–8000
блоков, это 10–13 минут при блоке в 100 мс. Балансы отставших бакетов уже не
восстановить — их надо пропустить, а не дозаполнять текущими значениями,
иначе продавший в простое майнер получит награду за баланс, которого у него
не было.

**Своп разворачивается с `Too little received`.** Цена ушла сильнее лимита
проскальзывания. Проверить глубину пула, прежде чем поднимать лимит: подъём
лимита без проверки глубины — это согласие на плохую цену.

**Кончился ETH у кипера.** Публикация и, что важнее, пауза станут
невозможны. Резерв `GAS_RESERVE_WEI` не свопается именно поэтому, но
пополнять кошелёк всё равно нужно.

**Одна стадия воркера падает, остальные работают.** Так и задумано: моргнувший
RPC на публикации не должен заодно выключать watchdog. Стадии изолированы,
каждая падает в свой алерт. Смотреть в stderr по префиксу `[ALERT`.

**Нужно остановить всё прямо сейчас.** Пауза доступна и киперу, и админу:

```bash
cast send $REWARD_VAULT "pause()" --private-key $KEY --rpc-url $RPC_URL
```

Снять паузу может только админ:

```bash
cast send $REWARD_VAULT "unpause()" --private-key $ADMIN_KEY --rpc-url $RPC_URL
```

Это разделение намеренное. Пауза ведёт в сторону безопасности, поэтому её
отдали горячему ключу; возврат в рабочий режим — нет, поэтому он остался за
холодным.
